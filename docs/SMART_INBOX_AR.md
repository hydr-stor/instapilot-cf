# Smart Inbox — دليل التنفيذ والتشغيل

التطوير في فرع feat/smart-inbox-human-takeover، انطلاقاً من main عند d676395.
لا يتضمن هذا العمل Push أو Merge أو نشر أو تنفيذ مهاجرة على قاعدة الإنتاج.
اسم Worker وإعدادات wrangler.jsonc وربط D1 الإنتاجي لم تتغير.

## ما نُفّذ

- الخلفية الحالية Cloudflare Workers + D1 موجودة بالفعل. التكامل **Instagram Login**؛ ليس Facebook Login.
- استُخدمت جلسة sid وصلاحية صاحب المتجر وتشفير AES-GCM الحالي دون إنشاء نظام حسابات بديل.
- أضيفت حالات AI_ACTIVE وHUMAN_ACTIVE وCLOSED، والمستخدم الذي استلم المحادثة، وعداد القراءة وسجل التحويل.
- استُخدم جدول messages الموجود للرسائل الواردة والسجل القديم. جداول جديدة للمحادثات والإرسال والتحويلات فقط.
- Webhook الموقّع يحفظ الوارد **قبل** إرسال HTTP 200. فشل الحفظ يُرجع خطأ لكي تعيد Meta التسليم.
- عداد غير المقروءة لا يزيد عند تكرار Webhook. حد القراءة مرتبط بمعرّف الرسالة، فلا يمسح واردًا أحدث وصل بالتزامن.
- كل قراءة وتغيير وإرسال مرتبط بمتجر المستخدم؛ معرّف محادثة متجر آخر يُرجع 404.
- الإرسال يستخدم رمز المتجر من الخلفية وSend API، ويحفظ معرّف Meta عند نجاحها فقط.
- حالات QUEUED وSENDING وSENT وFAILED وUNKNOWN وCANCELLED حقيقية؛ SENT تعني قبول Meta، وليست تأكيد قراءة الزبون.
- سجل إرسال بمفتاح idempotency يمنع تكرار الطلب. إعادة المحاولة متاحة صراحة بعد رفض مؤكد فقط.
- طلبات التدخل العراقي/العربي تغيّر الوضع وتضيف إشعاراً، ثم يُرسل تأكيد التحويل بعد نجاح التغيير الداخلي.
- الرسائل من تطبيق Instagram نفسه تظهر بوصفها EXTERNAL وتتوقف AI على المحادثة. Echo الخاص بإرسال التطبيق لا يسبب حلقة.
- واجهة RTL للموبايل والحاسوب: بحث، فلاتر، ترتيب، صفحات للرسائل القديمة، رد يدوي، استلام، إعادة AI، إغلاق وإعادة فتح.
- تحديث أثناء فتح الصندوق كل 4 ثوانٍ، وتنبيهات اللوحة كل 15 ثانية، مع إيقاف الاستعلامات عند إخفاء الصفحة وإلغاء الطلبات عند مغادرتها.
- لا توجد مكتبات UI أو خدمات مدفوعة جديدة. لا توجد بيانات مصطنعة في مسار الإنتاج.

## عدم الفهم والتدخل البشري

عندما يعيد المصنّف UNCLEAR، تكون رسالة الرد بالضبط:

    مافهمت عليك اعد صياغ الجملة وخليني افهمك زين

بعد الفشل الثاني تُرسل رسالة منفصلة تعرض التواصل مع التاجر. لا يحدث التحويل إلا بطلب واضح أو قبول العرض.
نقص معلومات المنتج يعامل كـ NO_KNOWLEDGE؛ لا يُحسب كعدم فهم ولا يحوّل تلقائياً كل سؤال إلى البشر.
أُدخلت الردود البشرية في سياق AI عند استئنافها، مع المحافظة على منطق المنتجات والحجوزات والإلغاء الحالي.

## التزامن والتعطل

D1 batch ينفذ التغييرات المرتبطة كمعاملة، وتُستخدم تحديثات شرطية وقفل إرسال لكل محادثة ومعرّف مستقل لمهمة AI.
استلام التاجر أثناء توليد الرد يلغي الإرسال الآلي قبل بدايته. إذا كان إرسال قد غادر إلى Meta بالفعل، يُرفض تغيير الوضع اليدوي مؤقتاً بدلاً من الادعاء بإيقاف رسالة خرجت.
طلب الزبون للتدخل يوقف أي إرسال آلي جديد فور حفظ وضع HUMAN_ACTIVE؛ رسالة بدأت قبل الطلب قد تصل، ولا يبدأ رد بشري حتى يُحسم إرسالها.

انقطاع الشبكة أو رد خادم Meta غير الحاسم قد يقع بعد قبول الرسالة. لا يوجد ضمان exactly-once من Meta بهذه الواجهة؛ لذلك لا نخفي هذا القيد بإعادة الإرسال.
تظل الحالة UNKNOWN والقفل محفوظاً. يمكن أن يؤكد Echo الموقّع الرسالة؛ أو يستخدم الدعم /api/inbox/reconcile مع معرّف Meta.
المسار يتحقق من الرسالة عبر Meta ومن الحساب والزبون والنص والتوقيت قبل حسمها. لا يوجد زر يعلنها «لم تُرسل» اعتماداً على التخمين.
لا تعاد مهمة AI المتعطلة إذا وُجد إرسال سابق لها. المهام التي لم تبدأ إرسالاً لها حد أقصى من محاولات الاسترداد.

سجل inbox_transfers ومعرّفات إشعارات notifs.inbox_event_id يصلحان كمصدر لأداة WhatsApp Business مستقبلية.
لا يوجد إرسال WhatsApp أو استخدام لرقم أو خدمة غير رسمية في هذا الإصدار.

## تجربة محلية تفاعلية

يلزم Node.js 24 أو أحدث لاختبارات SQLite المحلية فقط؛ هذا ليس تغييراً لإصدار تشغيل Cloudflare.

    npm test
    npm run preview:inbox

افتح على **الجهاز الذي شغّل الأمر**:

    http://127.0.0.1:3100/__local/start

المعاينة تشغّل Worker الحقيقي وSQL المهاجرة في SQLite داخل الذاكرة، مع بديل محلي كامل لطلبات Meta وAI.
تعرض شريطاً واضحاً بأن البيانات اختبارية، وتستخدم رموزاً مصطنعة فقط. لا تستدعي الإنتاج ولا تنشئ Worker أو D1.
رابط loopback ليس رابطاً خارجياً يمكن فتحه من آيفون بعيد. يلزم إعداد معاينة معزولة بموافقة منفصلة لتجربة حساب Meta حقيقي.
يمكن تغيير المنفذ باستخدام INBOX_PREVIEW_PORT. مسارات /__local/* موجودة في سكربت التطوير فقط؛ لا توجد في Worker أو public.

اختبار المتصفح الاختياري بعد تشغيل المعاينة:

    pip install -r tests/requirements.txt
    python -m playwright install chromium
    INBOX_PREVIEW_ORIGIN=http://127.0.0.1:3100 python tests/smart-inbox-ui.py

تقارير المتصفح الافتراضية في مجلد instapilot-smart-inbox-qa داخل مجلد الملفات المؤقتة.
يمكن تغيير INBOX_QA_OUTPUT وINBOX_CHROMIUM. اختبارات Chromium تحاكي حجم ولمس iPhone؛ لا تثبت سلوك Safari فعلي.

فحوص الواجهات السابقة متاحة أيضاً:

    python tests/legacy/run_merchant.py

نتائج التحقق في هذه البيئة: 35 حالة Backend/SQL، و12 مجموعة ربط للواجهة مع Backend محلي فعلي، و21 مجموعة انحدار للصفحات القديمة؛ نجحت كلها (68 إجمالاً). لم تظهر أخطاء JavaScript في المتصفح. نجح تجميع Worker كـ ESM للمتصفح/Workers باستخدام esbuild.
هذه النتائج تشمل محاكاة موثوقة لطلبات Meta، ولا تشمل وصولاً إلى حساب Instagram حقيقي أو جهاز iPhone فعلي.

## تفعيل Meta قبل الإطلاق

المسارات المطبقة تستخدم graph.instagram.com، ومعرّف الحساب المهني المتصل، وIG-scoped customer ID من Webhook.
لا تُستعمل صلاحيات Facebook Login أو رموز الصفحات بدلاً من رموز Instagram Login.

1. حساب Instagram Business أو Creator، وسماح الحساب للأدوات المتصلة بالوصول إلى الرسائل.
2. صلاحيتا instagram_business_basic وinstagram_business_manage_messages للتكامل الحالي.
3. App Review / Advanced Access ووضع التطبيق المناسب لحسابات تجار خارج فريق الاختبار، وأي تحقق تجاري تطلبه Meta.
4. تسجيل عنوان Webhook الحالي /webhook/instagram، وضبط IG_VERIFY_TOKEN وسر التطبيق الصحيح، والاشتراك في messages.
5. تسجيل redirect_uri الحالي /api/instagram/callback بالعنوان الإنتاجي المطابق. لم نبدّل state أو client_id أو scope أو مسار callback.
6. OAuth يحاول تأكيد اشتراك الرسائل ويحفظ نتيجته. يمكن للتاجر طلب تفعيل الاشتراك من الصندوق عند الحاجة، والرفض لا يظهر كنجاح.
7. HUMAN_AGENT يحتاج موافقة Meta الفعلية. IG_HUMAN_AGENT_APPROVED=true لا يمنح الموافقة؛ يتيح استخدامها فقط بعد تحقق الإدارة.
8. الوضع الافتراضي يمنع الإرسال بعد 24 ساعة. إذا اعتمدت Human Agent، يسمح الرد البشري الصريح خلال 7 أيام. AI وإشعارات النظام لا تستخدم هذا الوسم.
9. نحتاج اختباراً بحساب متجر وحساب زبون فعليين: منح الصلاحيات، التسليم من Webhook، إرسال رد، ظهوره عند الزبون، Echo، ثم الاستلام وإعادة AI.

مراجع Meta الرسمية:
- https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api
- https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/messaging-api/
- https://developers.facebook.com/docs/features-reference/human-agent/
- https://developers.facebook.com/docs/instagram-platform/webhooks/

التنفيذ يحافظ على v21.0 الموجود؛ IG_API_VERSION يتيح تغييراً مقصوداً بعد اختبار توافقه.
لم نختبر صلاحية التطبيق الحقيقية أو موافقات Meta من هذه البيئة. بعض صفحات توثيق Meta حجبت القراءة الآلية؛ يجب تأكيد أهلية Human Agent والإصدار من لوحة التطبيق قبل الإطلاق.

## تجهيز قاعدة البيانات والإصدار

المهاجرة migrations/0001_smart_inbox.sql إضافة فقط: لا تحذف جدولاً أو رسالة أو رمزاً.
تُطبّق مرة واحدة بواسطة نظام مهاجرات D1 بعد وجود جداول النظام القديم، وخارج طلبات HTTP.
طلبات الإنتاج لا تشغّل هذه المهاجرة تلقائياً.

تسلسل الإصدار الذي يحتاج مراجعة وموافقة مستقلة:
1. نسخة احتياطية قابلة للاستعادة، وتجربة المهاجرة على نسخة معزولة من قاعدة النظام القديم.
2. التحقق من عدم ربط حساب Instagram واحد بمتجرين. الإدخال يرفض الحالة الملتبسة ولا يختار تاجراً عشوائياً.
3. مراجعة الربط التاريخي: الرسائل القديمة لم تحفظ معرّف حساب Instagram؛ تربطها المهاجرة بالحساب الحالي للمتجر. إذا تبدل الحساب سابقاً يلزم تدقيق هذا التاريخ قبل إتاحة الإرسال.
4. نشر الشيفرة بعد الموافقة مع SMART_INBOX_ENABLED غير مفعّل، ثم تطبيق المهاجرة المعتمدة على قاعدة البيانات الصحيحة.
5. تفعيل SMART_INBOX_ENABLED=true بعد نجاح المهاجرة، والتأكد من LIVE وإعدادات Meta الحالية.
6. تجربة قبول بحسابات Meta فعلية وSafari على iPhone، ثم تشغيل تدريجي ومراقبة الأخطاء وحدود Meta.
7. اختبار حمل مناسب لحجم التجار. معالجة الخلفية تستفيد من Cron الموجود للاسترداد؛ الضغط العالي أو التوليد البطيء يحتاج تقييماً لـ Cloudflare Queues قبل التوسع.

الحقول المستوردة القديمة لا تفتح نافذة 24 ساعة؛ يلزم وارد حديث يحمل توقيت Meta موثّقاً.
يعرض الصندوق كل الرسائل المتاحة في قاعدة المشروع مع pagination؛ لا يدعي استيراد رسائل Instagram التاريخية التي لم يستقبلها المشروع.
النظام الحالي يملك صاحب متجر واحداً لكل متجر. assigned_user_id يسجل من استلمها وفق صلاحياته الحالية؛ إدارة فريق متعدد الأعضاء ليست مضافة هنا.

**تراجع آمن:** قبل إعادة Worker قديم أو تعطيل ميزة التحكم الجديدة بعد تشغيلها فعلياً، أوقف الإرسال الحقيقي مؤقتاً عبر LIVE بعد موافقة الإدارة.
النسخة القديمة لا تعرف أوضاع HUMAN_ACTIVE. لا تستخدم الرجوع إلى النسخة القديمة كوسيلة لتجاوز أقفال UNKNOWN.
لا تحذف جداول الإضافة عند التراجع؛ تحفظ المحادثات والإرسال والتحويلات، ولا تنفذ مهاجرة عكسية هادمة.
بعد المراجعة أعد الإرسال فقط مع سياسة تحفظ المحادثات التي استلمها البشر.
